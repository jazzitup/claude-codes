# HWP(X) 개인정보 양식 채우기

연구비/평가 서류 등에서 자주 요구하는 "개인정보 수집·이용 동의서", "전문가
신상정보", "고유식별번호 수집 양식" 같은 한글 문서 양식에 사용자의 실제
개인정보를 채워 넣는 작업. [[hwpxskill]]의 unpack→edit→pack 워크플로우를
그대로 쓰되, **개인정보 보안**에 특화된 추가 규칙이 있다.

## 0. 절대 규칙 (개인정보 보안)

- **이 스킬 문서(공개 git repo, `~/.claude/skills`)에는 실제 개인정보를
  단 한 글자도 적지 않는다.** 이름, 주민등록번호, 계좌번호, 전화번호,
  주소 — 전부 예시값도 포함해 적지 않는다. 아래 모든 예시는 구조 설명만
  한다.
- **작업용 unpack/edit 산출물은 전부 세션 스크래치패드
  (`/private/tmp/claude-*/.../scratchpad`)에서만 다룬다.** `~/.claude/`
  아래(스킬 디렉터리, 프로젝트 메모리 등 git 추적 대상)에는 절대 중간
  파일도 만들지 않는다.
- **최종 완성 파일은 사용자가 지정한 개인 폴더(원본 양식이 있던 폴더 등,
  Dropbox 개인서류류 위치)에만 저장한다.** git 저장소 어디에도 두지
  않는다.
- **채팅 응답에서도 민감정보를 과다 노출하지 않는다.** 어떤 필드를
  채웠는지 항목명은 보고하되, 주민등록번호·계좌번호 전체 자릿수를
  요약 메시지에 그대로 다시 타이핑하지 않는다(파일 안에는 정확히
  들어가 있어야 하지만, 대화 로그에 또 한 번 노출할 필요는 없다).
- **개인정보 출처**: 사용자가 별도로 알려준 로컬 참고 파일(이름/주민번호/
  계좌/연락처/주소 등을 모아둔 개인 RTF 등)에서 **매번 새로 읽어온다**.
  세션 메모리나 스킬 파일에 값을 캐싱하지 않는다 — 사용자가 그 파일에
  내용을 추가/수정하면 다음에 다시 읽을 때 반영돼야 한다.

## 1. .hwp만 있는 경우

[[hwpxskill]]은 `.hwp` 바이너리 직접 편집을 거부한다. 사용자가 `.hwp`
원본만 줬다면:

1. 이 Mac에는 **Hancom Office HWP.app**이 설치돼 있다(`/Applications/`
   확인됨). 사용자에게 그 앱에서 원본 `.hwp`를 열고 **다른 이름으로
   저장 → 파일 형식: HWPX**로 저장해 달라고 안내한다.
2. 사용자가 `.hwpx`로 다시 저장해서 경로를 주면 그 파일로 이어서
   작업한다.
3. 최종 결과물을 다시 `.hwp`로 돌려달라는 요청이 있으면, 완성된
   `.hwpx`를 Hancom Office에서 열어 `.hwp`로 저장하는 것도 사용자가
   직접 하거나(가장 확실), 필요하면 GUI 자동화(`osascript`)로 Hancom
   Office를 조작해 대신 저장할 수 있는지 시도해본다 — 이 경우도 앱이
   실제로 그 포맷 변환을 수행하는 것이지 이 스킬이 바이너리를 직접
   만드는 게 아니므로 0절/hwpxskill 규칙과 충돌하지 않는다.

## 2. 빈 칸 구조 파악

1. [[hwpxskill]]의 `hwpx_slots.py`와 `text_extract.py --include-tables`로
   전체 문항/표를 훑어 어떤 라벨에 어떤 값이 필요한지 표로 정리한다.
2. `office/unpack.py`로 풀어서 원본 XML을 직접 본다. 빈 입력칸은 보통
   `<hp:run charPrIDRef="N"/>`처럼 **`hp:t`가 아예 없는 self-closing
   run**으로 나타난다 — 라벨 셀(`<hp:tc>...</hp:tc>`)이 닫힌 바로
   다음 `<hp:tc>`가 그 라벨의 값 칸인 경우가 많다.
3. 체크박스는 문서마다 두 가지 패턴이 섞여 있을 수 있다:
   - **대괄호형**: 한 런 안에 `[ ] `처럼 텍스트로 박혀 있음 → 그
     자리를 `[■] ` 같은 걸로 바꾼다(대상 항목 뒤에 오는 고유한 라벨
     텍스트를 앵커로 삼아 유일성 확보).
   - **2열 미니테이블형**: `[라벨 셀 | 체크마크 셀]`이 옵션마다 각각
     별도의 작은 표로 반복됨. 체크마크(`√` 등)가 이미 원하는 라벨
     옆 칸에 들어있는지, 아니면 다른(원치 않는) 옵션 옆에 들어있는지
     라벨 셀이 닫히는 지점과 다음 셀의 `<hp:run charPrIDRef="N"/>`
     (비어있음) 여부를 직접 XML에서 확인하고 판단한다 — 슬롯
     프리뷰만 보고 짐작하지 않는다.

## 3. 값 채우기

1. 각 빈 셀/런에 대해 `<hp:run charPrIDRef="N"/>` →
   `<hp:run charPrIDRef="N"><hp:t>값</hp:t></hp:run>`으로, 기존
   placeholder 텍스트가 있는 칸은 `<hp:t>기존값</hp:t>` →
   `<hp:t>새값</hp:t>`으로 Python 문자열 치환한다. **치환 전 반드시
   해당 부분이 파일 전체에서 정확히 1번만 나오는지 확인**하고(안
   그러면 라벨 텍스트 같은 더 넓은 문맥을 앵커에 포함), 1번이 아니면
   중단하고 앵커를 넓힌다.
2. `hp:tab`, `hp:fwSpace`, `hp:lineBreak` 같은 `hp:t` 내부 자식
   컨트롤은 절대 지우지 않는다 — 그 자식들의 앞/뒤 텍스트(`text`/
   `tail`)만 바꾼다. 예: "이름란        (서명 또는 인)" 같은 줄에서
   탭 문자들 사이에 이름을 끼워 넣을 땐, 탭 요소들은 그대로 두고
   라벨 뒤 공백 부분에만 이름을 넣는다.
3. 날짜 양식(`202X 년   X 월   XX 일`류)은 빈칸 개수/공백 패턴을
   최대한 유지하면서 실제 연/월/일 숫자만 채운다.
4. 판단이 필요한 필드(예: 소속 형태 체크박스가 공무원/공직유관단체/
   학교 교직원/언론사/해당없음 중 어디에 해당하는지, 거주자/비거주자
   전용 칸 처리)는 사용자의 실제 소속·신분에 맞게 스스로 판단해
   채우되, 판단 근거를 최종 보고에 한 줄로 남긴다. 애매하면 채우지
   말고 사용자에게 묻는다(전화번호처럼 이 스킬이 알 수 없는 값을
   추측해서 채우지 않는다 — [[receipt-scan]] 2b절과 같은 원칙).
5. 서명란: "(서명 또는 인)" 앞에 인쇄용 이름만 채우고, 그 이상(실제
   서명 이미지·도장)은 만들지 않는다 — 사용자가 인쇄 후 직접 한다.

## 4. 패키징 및 검증 (hwpxskill 필수 게이트)

```bash
python3 office/pack.py <unpacked_dir> <output>.hwpx
python3 fix_namespaces.py <output>.hwpx
python3 finalize_hwpx.py <output>.hwpx --strip-linesegarray --layout
python3 validate.py <output>.hwpx --layout
python3 page_guard.py --reference <원본>.hwpx --output <output>.hwpx \
  --skip-text-drift --allow-empty-fill --no-strict-paragraph-budget
python3 content_guard.py <output>.hwpx --rules rules.json
```

`content_guard.py`의 `rules.json`은 **채워 넣은 실제 값을 스크래치패드
파일에만 적는다**(git 밖). `require`에 새로 채운 값들, `forbid`에
원본의 placeholder(예시 이름, 예시 전화번호, `XXXXX`류)를 넣어 잔재가
없는지 반드시 확인한다.

## 5. 파일명 및 저장

- 관찰된 관례: 원본 파일명이 "(양식) OOO.hwp(x)"면, 완성본은 "(양식)"을
  빼고 사용자 이름을 대괄호로 넣은 "[이름] OOO.hwpx"로 저장한다(사용자가
  다른 규칙을 말하면 그걸 따른다).
- 저장 위치는 원본 양식이 있던 폴더(또는 사용자가 명시한 폴더)로,
  원본 파일은 그대로 둔다(삭제/덮어쓰기 하지 않음).
