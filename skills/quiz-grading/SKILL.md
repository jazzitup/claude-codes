# 퀴즈 채점 (스캔 답안지 → 점수 엑셀)

## 0. 입력물 파악

보통 이런 파일들이 주어진다 (`quiz/quizN/` 폴더 안, 2026-09-22
`Quiz2_2026-09-22` 기준 확인된 패턴):
- `QuizN_YYYY-MM-DD.docx` (+ 같은 이름의 `.md`) — 문제지. **`.md`가 있으면
  그걸 읽는다** (docx보다 훨씬 빠르고 정확 — `.docx`는 스킬 로드 없이는
  Read 도구가 제대로 못 읽을 수 있다).
- `QuizN_YYYY-MM-DD_sol.docx` (+ `.md`) — 정답지. 마찬가지로 `.md` 우선.
- `HPSCAN_..._....pdf` 파일 1~2개 — 스캔된 답안지. **양면 스캔이면 2개**
  (한 면씩 따로 스캔 후 합친 것 — "한번 한면만 스캔하고 뒤집어서 반대편
  스캔"하는 방식이 확인됨, 아래 1단계 참고).
- (있으면) `학생 리스트.xlsx` — 실제 명단(학번, 영문 이름). 보통 강의
  디렉토리 최상위에 있다 (`.../수업 2026 fall/학생 리스트.xlsx`).
  **이름 OCR이 애매하면 반드시 이걸로 학번 대조해서 확정한다** — 손글씨
  이름 추측보다 압도적으로 정확하다 (2026-09-22에 14명 전원이 학번
  매칭 한 방에 확정됨, 오독했던 학번 앞자리도 여러 개 바로잡힘).

문제/정답 `.md`를 읽어서 (1) 각 문제가 몇 점인지(사용자가 알려줌, 보통
문제 개수로 등분), (2) 정확한 정답 코드, (3) PennyLane alias가 `qml`인지
`qp`인지(문제마다 다를 수 있다 — 최근엔 코드북 자체가 `qp`를 쓰는 추세,
`pennylane-codercise-notebook` 스킬에서도 확인된 패턴)를 파악한다.

## 1. 스캔 페이지 순서 파악 — 절대 페이지 번호로 안 맞는다

**흔한 함정**: "학생1 앞면, 학생1 뒷면, 학생2 앞면..." 처럼 스캔1의 N번째
페이지가 스캔2의 N번째 페이지와 같은 학생일 거라 가정하면 **틀린다**.
실제로는 (2026-09-22, 14명/28페이지 기준 확인):

- 스캔1과 스캔2 안에서도 문제1/문제2가 섞여 있을 수 있다(앞부분은 문제1
  전부, 뒷부분은 문제2 전부인 식 — 학생마다 어느 쪽이 "앞면"이었는지가
  일정하지 않기 때문).
- 사용자가 "한 면만 스캔하고, 그 다음 종이 뭉치를 통째로 뒤집어서 반대편을
  스캔"하는 방식을 쓰면, **스캔2의 순서는 스캔1과 정확히 반대로 뒤집힌다**:
  스캔1의 N번째 페이지 = 스캔2의 `(총페이지수+1-N)`번째 페이지. (총
  28페이지, 14명이면 `15-N`.) 종이를 통째로 뒤집었으므로 스캔2의 각
  페이지는 스캔1과 무관하게 낱장별로 위아래가 뒤집혀 있을 수도, 아닐
  수도 있다(스캐너의 자동 회전 보정이 페이지마다 다르게 걸리는 듯) —
  **회전은 페이지별로 직접 눈으로 봐서 판단**해야 하고, 순서 공식만
  믿으면 된다.
- 이 공식은 **처음부터 가정하지 말고, 실제로 읽은 학번 2~3쌍으로
  검증**한 뒤 확정한다: 스캔1의 어떤 페이지 학번과 스캔2의 `15-N`번째
  페이지 학번이 일치하는지 먼저 3~4쌍 확인하고, 맞으면 나머지는 그
  공식으로 빠르게 매칭한다. 안 맞으면(사용자마다 스캔 방식이 다를 수
  있음) 사용자에게 "이번 스캔 순서가 어떻게 되는지" 직접 물어보는 게
  낫다 — 혼자 추측으로 계속 페이지를 뒤적이는 것보다 훨씬 빠르다.
- 뒤집혀서 나온(upside-down) 페이지도 `Read`가 그대로 이미지를 보여주며,
  글자를 거꾸로 읽는 건 충분히 가능하다 — 굳이 회전시켜서 다시 저장할
  필요 없다.

## 2. 채점 루브릭

- 문제당 배점은 사용자가 알려준 대로 등분(예: 2문제×10점=20점 만점).
- **코드가 실제로 돌아가고 요구사항을 만족하면 만점.**
- **완전 백지이거나 완전히 틀리면 0점.**
- **부분점수는 Claude 판단으로 적당히** — 다만 아래 기준을 따른다
  (2026-09-22 세션에서 사용자가 실시간으로 조정해준 기준):
  - **단순한 오타(simple typo)는 하나당 0.2점만 깎는다.** 예: 수학
    표기대로 `i`/`-i`를 그대로 써서 파이썬 문법상 `1j`/`-1j`가 필요한
    걸 놓친 경우(허수단위 리터럴은 숫자 계수가 꼭 있어야 함 — `i`나
    `j` 단독은 NameError), `np.array(a, b)`처럼 리스트 대괄호를 빼먹어
    TypeError가 나는 경우 등. **어떤 학생 하나가 특정 오타를 냈다면
    반 전체에서 같은 오타가 반복해서 나올 수 있다** (2026-09-22엔
    "허수단위를 i로 씀" 오타가 14명 중 대부분에게서 나왔다 — 문제
    자체가 수식에서 $-i$로 표기해서 유도된 자연스러운 실수) — 매번
    똑같이 0.2×횟수로 일관되게 채점한다.
  - 같은 이슈가 한 줄에서 여러 번 반복되면(예: 게이트 5줄 모두
    `qp.` 대신 `qml.`을 쓴 경우) "간단한 오타"로 보되, 5번 다
    0.2×5로 깎지 말고 **하나의 체계적 실수로 보아 합쳐서 0.3~0.5점
    정도만** 깎는다 — 그 학생이 논리를 이해했다는 게 명백하기 때문.
  - **함수 본문이 통째로 비어있으면**(핵심 요구사항—예: 실제 게이트
    적용—을 아예 안 한 경우) 나머지 부분(예: 행렬 정의)이 맞았어도
    큰 폭으로 깎는다. "정의는 맞았지만 적용을 안 함" 같은 경우
    문제 배점의 30~40% 정도만 준다.
  - 완전히 다른 접근(예: 튜플로 반환, `conjugate` 대신 `transpose`
    사용처럼 개념 자체가 틀림)은 부분점수를 낮게(문제 배점의
    10~30%) 준다.

## 3. 이름/학번 확정

- 1차로 손글�스를 최대한 읽되, **`학생 리스트.xlsx`가 있으면 반드시
  대조**한다 (엑셀은 `openpyxl`로 `data_only=True`로 읽는다 — 시트
  이름, 컬럼(`ID number`, `Fullname`)을 확인). 학번은 숫자라 손글씨
  오독이 잦으므로(특히 앞자리 0/2, 뒷자리 유사 숫자), **손글씨로 읽은
  학번과 로스터 학번이 1~2자리만 다르면 로스터 쪽을 채택**한다(로스터가
  틀릴 이유가 없으므로). 로스터에 있는데 답안이 없는 학번은 **결시자**로
  따로 표시한다.
- 로스터가 없으면(Quiz1 사례, 2026-09-03) 순번(스캔 페이지 순서, 100%
  확실)을 기본 키로 삼고 이름/학번은 "(미상)"으로 남긴 채 사용자에게
  나중에 명단으로 고쳐달라고 안내한다 — 억지로 확정 짓지 않는다.

## 4. 결과물: Excel

`anthropic-skills:xlsx` 스킬을 그대로 따른다. 이 Mac은 시스템 Python에
`openpyxl`이 안 깔려 있고 `pip install`은 PEP668(externally-managed)에
막히므로, **스크래치패드에 venv를 만들어서 설치**한다:

```bash
python3 -m venv "$SCRATCH/xlsxenv"
source "$SCRATCH/xlsxenv/bin/activate"
pip install --quiet openpyxl
```

이 Mac에는 LibreOffice(`soffice`)도 없어서 `xlsx` 스킬이 요구하는
`recalc.py`(수식 재계산 검증)를 못 돌린다 — **아주 단순한 합계/평균
수식**(`=D2+E2`, `=AVERAGE(...)`) 정도만 쓸 거면, LibreOffice 설치를
사용자에게 강요하지 말고 그냥 넘어가도 된다(실제 Excel/Numbers/Sheets가
열 때 알아서 재계산하므로 실무상 문제 없음) — 단, 이 사실을 사용자에게
한 줄로 알려준다. 복잡한 수식을 쓸 일이 생기면 그때 LibreOffice 설치
여부를 물어본다.

시트 구성: `순번, 이름, 학번, 문제1(N점), 문제2(N점), 총점(수식), 비고`.
`비고` 열에 채점 근거(왜 몇 점 깎았는지)를 학생마다 한 줄로 남긴다 —
나중에 사용자가 이의제기 대응할 때 바로 쓸 수 있게. 결시자는 표 아래
별도 섹션에, 그리고 신뢰도가 낮은(예: 뒤집힌 페이지라 필체 판독이
어려웠던) 행은 비고에 "재확인 권장"을 명시한다.

파일명은 `QuizN_YYYY-MM-DD_채점결과.xlsx`로, 같은 `quiz/quizN/` 폴더에
저장한다.

## 알아둘 것

- 학생 수가 많으면(2026-09-22 기준 14명, 28페이지) 한 번에 여러 페이지를
  `Read`로 몰아서 보면 이름/학번을 서로 헷갈리기 쉽다 — **4페이지(학생
  2명)씩 나눠서 순서대로** 읽는 게 훨씬 정확하다(Quiz1, Quiz2 세션
  둘 다 이 패턴으로 수습했다).
- PDF 페이지를 이미지로 렌더링하려면 `poppler`(`pdftoppm`)가 필요하다 —
  없으면 `brew install poppler`로 설치(1회성, 이후 세션에도 남아있음).
- 실행 결과(채점 근거)는 반드시 실제로 손으로 코드를 검산하거나 numpy로
  돌려봐서 확인한다(예: `abs(z)**2 == abs(z**2)`가 성립하는지, 특정
  변형이 정말 오답인지) — 겉보기에 비슷해 보이는 코드도 수학적으로
  다를 수 있다.
