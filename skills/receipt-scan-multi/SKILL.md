# 여러 영수증이 섞인 스캔본 분리·정리

연구비/카드 사용내역 정산용으로, 영수증 여러 장을 평판 스캐너에 아무렇게나
(각도 제각각으로) 늘어놓고 한 번에 PDF로 스캔한 파일을 받아서, 영수증
한 장당 이미지 파일 하나씩으로 잘라내는 작업이다.

## 0. 핵심 원칙

- **한 페이지 안에서도 영수증마다 회전 각도가 다 다르다.** 페이지 전체를
  한 번에 회전시키는 게 아니라, 영수증마다 개별적으로 올바른 방향을
  찾아야 한다 — 페이지의 "대표 회전값"에 맞춰놓고 나머지도 그럴 거라고
  가정하지 않는다(실제로 한 페이지 안에 0°로 바로 읽히는 영수증과 90°/
  180° 돌려야 읽히는 영수증이 섞여 있는 경우가 흔하다).
- **자르기 전에 반드시 잘린 부분이 없는지 눈으로 확인한다.** 특히
  날짜·합계 줄이 크롭 경계에 걸쳐 있으면 박스를 넉넉히 넓혀 다시
  자른다 — 금액/날짜가 잘려서 안 보이면 그 크롭은 실패다.
- **금액은 최종 합계("합계"/"총액"/"받을금액"/받은금액, 부가세 포함된
  마지막 총액)를 쓴다.** 소계(공급가액)나 부가세만 따로 쓰지 않는다.
- **날짜는 영수증에 찍힌 거래일시**를 쓴다(스캔한 날짜나 파일의 수정일이
  아니다).
- **통화 판단**: 기본은 원(KRW). 일본 영수증(¥ 표시, 일본 주소·전화번호
  형식 03-/06- 등)은 엔, 미국 영수증($ 표시)은 달러로 적는다.

## 1. PDF/이미지를 고해상도 이미지로 변환

```bash
pdftoppm -r 300 -png "<scan>.pdf" "<scratch>/hiN"
```
(이미 이미지 파일이면 이 단계 생략, 다만 원본 해상도가 낮으면 크롭 후
글자가 안 보일 수 있으니 확인)

## 2. 페이지를 훑어보고 영수증 목록 만들기

1. 300dpi PNG를 통째로(축소해서) 봐서 몇 장의 영수증이 있는지, 각각
   대략 어느 위치에 어느 각도로 붙어 있는지 파악한다. 페이지가 통째로
   90°/180° 돌아가 있으면(세로 스캔인데 옆으로 찍힌 등) 먼저 전체를
   그 각도로 돌려서 기본 방향을 맞춘다:
   ```python
   from PIL import Image
   im = Image.open("hiN-1.png")
   im.rotate(-90, expand=True).save("rot_hiN-1.png")  # 각도는 실제로 보고 판단
   ```
2. 회전 후 다시 축소본을 봐서, 이 "기본 회전"으로 몇 개가 바로 읽히는지,
   몇 개는 여전히 안 맞는지 확인한다. 안 맞는 것들은 4단계에서 개별
   추가 회전을 적용한다.
3. 각 영수증의 대략적 픽셀 좌표(bounding box)를 축소본 기준으로
   어림잡는다(축소 배율만큼 나중에 다시 곱해서 원본 해상도 좌표로
   환산).

## 3. 영수증마다 크롭

```python
from PIL import Image
im = Image.open("rot_hiN-1.png")  # 또는 회전 안 한 원본
crop = im.crop((left, top, right, bottom))  # 원본 해상도 좌표, 넉넉하게
crop.save("cX_name.png")
```

- 같은 물리적 영수증이 종이 한 장이 아니라 **같은 거래의 영수증 + 카드
  승인전표 두 장이 나란히 붙어 있는 경우**(일본식 매장에서 흔함 — 품목
  영수증과 신용카드 매출전표가 따로 인쇄됨), 둘을 각각 따로 만들지
  않고 **한 크롭 박스에 같이 담아 한 장으로 낸다**(같은 거래를 파일
  두 개로 중복 생성하지 않기 위해).

## 4. 낱장별 추가 회전 및 확인

같은 페이지 기본 회전으로 안 맞는 크롭은 개별적으로 더 돌린다(보통
0°/±90°/180° 중 하나). 돌린 뒤 **반드시 Read로 열어서 눈으로 확인**한다:
- 글자가 똑바로 읽히는지
- 금액/날짜 줄이 잘리지 않았는지(잘렸으면 2단계 박스를 넓혀 다시 자름)

## 5. 금액·날짜·통화 읽기

각 크롭에서:
- **금액**: 최종 합계(세금 포함, 맨 아래/마지막 총액)
- **날짜**: 영수증에 인쇄된 거래일시(YYYY-MM-DD)
- **통화**: 0절 기준으로 판단

모호하면(흐릿함, 여러 후보 합계, 손글씨 등) 추측하지 말고 사용자에게
확인을 구한다 — [[receipt-scan]] 2b절과 동일한 원칙.

## 6. 중복 처리

여러 스캔 파일에 같은 상호·같은 금액·같은 날짜의 영수증이 두 번 이상
나오면(대개 첫 스캔에서 페이지 경계에 걸려 잘렸다가 다시 스캔한 경우),
**내용이 잘리지 않고 완전한 쪽 하나만** 최종 결과물로 남기고 나머지는
버린다. 어느 쪽이 완전한지는 날짜·합계 줄이 온전히 다 보이는지로
판단한다.

## 7. 파일명 짓기 및 저장

- 파일명: `<금액><통화>_YYYY.MM.DD.jpg` — 금액은 천단위 구분자 없는
  정수(예: `13900원`, `6800엔`), 날짜는 점으로 구분한 `YYYY.MM.DD`.
- 포맷은 PNG가 아니라 **JPG**로 저장한다(영수증 스캔 크롭은 사진성
  콘텐츠라 JPG가 같은 화질에 용량이 훨씬 작고, 변환 수고도 PNG와
  동일하다 — "용량과 수고가 덜 드는 쪽"의 기본 선택).
- 긴 변 기준 1600px 정도로 리사이즈, quality~85 — 대체로 100~300KB대로
  나온다:
  ```python
  im = Image.open(cropped).convert("RGB")
  w,h = im.size
  if max(w,h) > 1600:
      s = 1600/max(w,h)
      im = im.resize((int(w*s), int(h*s)), Image.LANCZOS)
  im.save(dest_path, "JPEG", quality=85)
  ```
- 저장 위치: 사용자가 지정한 폴더에 저장한다(매번 요청 시 목적지를
  명시하거나, 최근에 지정한 폴더가 있으면 확인 후 재사용). 폴더가 없으면
  만들어서 저장한다.
- 원본 스캔 PDF는 그대로 둔다(삭제하지 않음) — [[receipt-scan]] 5절과
  동일한 원칙, 사용자가 명시적으로 지우라고 하지 않는 한 원본 보존.

## 8. 보고

작업이 끝나면 표로: 원본 스캔 파일명 → 그 안에서 찾은 영수증들(상호,
금액, 날짜) → 최종 파일명, 그리고 중복으로 판단해 제외한 항목이 있으면
왜 제외했는지(어느 쪽을 남겼는지) 짧게 알려준다.
