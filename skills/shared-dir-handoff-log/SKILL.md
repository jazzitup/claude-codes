# 공유 디렉토리 인수인계 로그

## 0. 왜 필요한가

Claude Code의 대화 기록(`~/.claude/projects/<경로>/*.jsonl`)과 메모리
(`~/.claude/projects/<경로>/memory/`)는 **그 컴퓨터에만** 있다. 작업 폴더가
Google Drive/Dropbox로 여러 컴퓨터에 공유돼도 Claude의 기억은 따라가지 않는다.
그래서 다른 컴퓨터에서 "하던 일 기억해?"라고 물으면 아무것도 모른다
(2026-11-24, `HIMAC beam time 2026` 폴더에서 실제로 겪음).

해결: 인수인계에 필요한 것을 **공유 폴더 안의 .md 파일**로 남기고, 그 폴더의
`CLAUDE.md`가 매 세션에 "먼저 읽어라 / 중간중간 남겨라"를 지시하게 한다.
`CLAUDE.md`는 폴더와 함께 동기화되므로 어느 컴퓨터에서 열어도 자동 적용된다.

## 1. 만들 파일 (대상 디렉토리 기준)

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 규칙: 세션 시작 시 로그 읽기 + 작업 중 로그 남기기 |
| `claude notes/SESSION_LOG.md` | 무슨 일이 있었나 (append 전용) |
| `claude notes/<프로젝트>_TODO.md` | 지금 남은 일 (있으면 그대로 쓰고, 없으면 사용자가 원할 때만 만든다) |

이미 `CLAUDE.md`가 있으면 덮어쓰지 말고 아래 2절 내용을 **섹션으로 추가**한다.
이미 `SESSION_LOG.md`가 있으면 새로 만들지 말고 항목만 추가한다.
노트 폴더 이름이 이미 다르게 있으면(`notes/`, `claude notes/` 등) 있는 것을 따른다.

## 2. CLAUDE.md에 넣을 내용

프로젝트 이름만 바꿔서 그대로 쓴다.

```markdown
# <프로젝트 이름> — Claude 작업 규칙

이 디렉토리는 <Google Drive 등>으로 **여러 컴퓨터가 공유**한다. Claude Code의 대화 기록과
메모리(`~/.claude/...`)는 컴퓨터마다 따로라서 다른 컴퓨터로 넘어가지 않는다.
인수인계는 오직 이 디렉토리 안의 로그 파일로만 한다.

## 세션 시작할 때 (항상)

1. `claude notes/SESSION_LOG.md`를 읽는다 — 최근 항목(맨 아래)부터 보고, 진행 중이던 일과
   "다음 할 일"을 파악한다.
2. `claude notes/<프로젝트>_TODO.md`(할 일 체크리스트)가 있으면 함께 읽는다.
3. 사용자가 "하던 일 이어서"라고 하면 로그의 마지막 "다음 할 일"부터 시작한다.

## 작업 중 로그 남기기 (항상)

`claude notes/SESSION_LOG.md` **맨 아래에 추가**한다(기존 항목은 고치거나 지우지 않는다 —
다른 컴퓨터와 동시에 쓰일 수 있으므로 append만).

언제 남기나:
- 의미 있는 단계가 끝날 때마다(메일 발송/초안 작성, 서류 작성·수정, 결정 사항, 확인된 사실).
  세션 끝에 몰아서 쓰지 않는다 — 세션은 예고 없이 끊길 수 있다.
- 사용자가 방향을 정하거나 바꿨을 때.
- 세션을 마무리할 때(또는 긴 작업을 멈출 때)는 "다음 할 일"을 반드시 적는다.

항목 형식:

    ## YYYY-MM-DD HH:MM KST — <컴퓨터 이름(`hostname -s`)>
    - **한 일**: 무엇을 했는지, 만든/고친 파일은 이 디렉토리 기준 상대경로로
    - **결정/확인된 사실**: 사용자가 정한 것, 메일에서 확인한 것(누가·언제)
    - **미해결/막힌 것**: 있으면
    - **다음 할 일**: 다른 컴퓨터의 Claude가 바로 이어갈 수 있을 만큼 구체적으로

쓰는 법:
- 날짜·시각은 `date`로 실제 값을 확인해서 적는다. 상대 표현("어제", "다음 주") 대신 날짜를 쓴다.
- 이 대화를 못 본 사람이 읽어도 이해되게 쓴다 — 사람 이름·메일 주소·파일 경로를 풀어서.
- 여권번호·주민번호·카드번호 같은 민감 정보는 로그에 적지 않는다.
- 경로는 컴퓨터마다 다르므로 절대경로 대신 이 디렉토리 기준 상대경로를 쓴다.

## 할 일 체크리스트

TODO 파일의 항목이 끝났거나 새로 생기면 그 파일도 같이 갱신한다(체크 표시, 날짜 덧붙이기).
로그는 "무슨 일이 있었나", TODO는 "지금 남은 일"이다.
```

## 3. SESSION_LOG.md 첫 항목 채우기

파일 머리말:

```markdown
# <프로젝트 이름> — 세션 로그

여러 컴퓨터의 Claude Code 세션이 인수인계하려고 남기는 기록. 규칙은 `../CLAUDE.md` 참고.
새 항목은 **맨 아래에 추가**한다(기존 항목은 고치지 않는다).
```

첫 항목에는 "로그 체계를 만들었다"와 함께, **과거 작업을 복원할 수 있는 만큼** 적는다.
대화 기록이 없어도 흔적은 남아 있는 경우가 많다:

- 디렉토리 안의 기존 노트·TODO·초안 파일(수정 날짜순 `ls -lat`)
- 이 컴퓨터의 `~/.claude/projects/<cwd의 영숫자 외 문자를 '-'로 바꾼 이름>/`
  - `*.jsonl` — 이전 세션 대화(있으면 user/assistant 텍스트만 뽑아 읽는다)
  - `<세션ID>/tool-results/*.txt` — 대화 기록이 없어도 큰 도구 결과는 남는다
    (어떤 메일 스레드를 열었는지 등)
  - `memory/` — 이 컴퓨터에만 있는 메모리. 인수인계에 필요한 내용이면 로그로 옮긴다

복원한 내용은 **확인된 것과 추정을 구분**해서 적는다("흔적으로만 확인", "결론은 기록 없음").
모르는 것을 지어내지 않는다.

## 4. 주의

- **심볼릭 링크**: 사용자가 `~/claude_workspace/<이름>` 같은 링크로 폴더를 여는 경우가 있다.
  파일은 링크가 가리키는 실제 공유 폴더에 써지므로 문제없다. 다만 프로젝트 메모리 폴더 이름은
  실제 경로 기준이라 컴퓨터마다 다를 수 있다 — 그래서 메모리가 아니라 로그를 쓴다.
- **동기화 충돌**: 두 컴퓨터가 동시에 같은 파일을 고치면 Drive가 충돌 사본을 만든다. append만
  하고, 쓰기 직전에 파일을 다시 읽어 최신 상태에 붙인다. 충돌 사본(`... (1).md`)이 보이면
  내용을 합쳐서 하나로 정리하고 사용자에게 알린다.
- **이 스킬 이후의 세션**: 규칙은 그 폴더의 `CLAUDE.md`가 직접 적용하므로 이 스킬을 다시
  부를 필요는 없다. 이 스킬은 체계를 **처음 만들 때**(또는 다른 공유 폴더에 똑같이 깔 때) 쓴다.
- 만들고 나면 사용자에게 "어떤 파일을 만들었고, 앞으로 어떻게 동작하는지"만 짧게 알린다.
