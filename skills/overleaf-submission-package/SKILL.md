# Overleaf → 투고용 소스 꾸러미

Overleaf에서 쓰던 논문을 저널(Elsevier 등)에 올릴 때 필요한 정리 작업을 한 번에 한다.
핵심은 **PDF가 바뀌지 않는 범위에서만** 지우고, 그 사실을 컴파일해서 확인하는 것이다.

## 1. 결과물

지정한 폴더 하나에, 하위 폴더 없이:

- `<원본이름>_sub.tex` — 주석과 안 쓰는 매크로를 지운 투고용 .tex
- `.bib` (그리고 프로젝트에 자체 `.bst`가 있으면 그것도)
- `.tex`가 실제로 부르는 그림 파일만

컴파일된 PDF, `.bbl`, `.aux` 같은 빌드 산출물은 넣지 않는다(사용자가 원하면 따로 추가).
원본 `.tex`는 Overleaf에 그대로 백업으로 남긴다.

## 2. 절차

### 2-1. Overleaf에서 소스 받기

1. 사용자가 Chrome에서 Overleaf에 로그인해 있어야 한다(로그인은 대신 하지 않는다).
2. claude-in-chrome으로 탭을 열고 아래 주소로 이동하면 프로젝트 전체 zip이 `~/Downloads`에 받아진다.
   `https://www.overleaf.com/project/<프로젝트ID>/download/zip`
   - 프로젝트 ID는 프로젝트 URL의 `/project/` 뒤 24자리.
   - 같은 이름이 이미 있으면 `이름 (1).zip`처럼 번호가 붙는다. `ls -t ~/Downloads | head`로 방금 받은 파일을 확인한다.
   - 내려받기는 사용자가 "다운받아"라고 요청한 경우에만 한다.
3. zip은 **새 빈 폴더**(세션 스크래치패드 아래)에 푼다. 프로젝트 폴더나 스크립트가 있는 폴더에 풀지 않는다.

### 2-2. 꾸러미 만들기 (스크립트)

```bash
python3 "$SKILL_DIR/scripts/make_submission.py" \
  --src  <zip을 푼 폴더> \
  --tex  main_v2.tex \
  --out  "<투고 폴더>" \
  --name main_v2_sub.tex
```

스크립트가 하는 일:

| 단계 | 내용 |
|---|---|
| 주석 | 주석만 있는 줄은 줄째 삭제. 코드 뒤 주석은 `%`부터 잘라냄. **줄 끝의 맨 `%`는 유지**(매크로 정의 안의 공백 억제용 — 지우면 PDF가 달라질 수 있음). `\%`는 건드리지 않음. |
| 매크로 | 프리앰블의 한 줄짜리 `\newcommand`/`\def` 중 어디에서도 쓰이지 않는 것 삭제. `\renewcommand`와 `@`가 든 이름은 유지. `--keep-macros`로 끔. |
| 빈 줄 | 연속된 빈 줄을 하나로. |
| 그림 | `\includegraphics`가 부르는 파일만 복사. 경로의 하위 폴더를 없애고 `.tex`의 경로도 고침. `--no-flatten`으로 끔. |
| 그 밖 | `\bibliography{}`의 `.bib`, 프로젝트에 있는 `.bst` 복사. |
| 검증 | 원본과 결과를 각각 임시 폴더에서 `latexmk -pdf`로 컴파일해 쪽수와 `pdftotext` 결과를 비교. 다르면 종료 코드 1. `--no-compile`로 끔. |

출력 폴더는 비어 있어야 한다(기존 파일을 덮어쓰지 않으려는 것). 그림 파일이 없거나 평탄화할 때 이름이 겹치면 아무것도 쓰지 않고 멈춘다.

### 2-3. 결과 보고

스크립트 출력을 그대로 요약해 사용자에게 알린다. 특히:

- 줄 수 변화, 지운 주석·매크로 개수
- 뺀 파일 목록(안 쓰는 그림, 다른 `.tex`)
- 컴파일 성공 여부, 쪽수, "PDF 본문 텍스트 비교: 같음/다름"
- BibTeX 경고(예: 어떤 항목의 year가 비어 있음)
- `주의:`로 나온 항목 — ASCII가 아닌 파일명, `\input`/`\include`, `\graphicspath`

## 3. Overleaf 안에도 `_sub.tex`를 둘 때

사용자가 Overleaf 프로젝트 안에 투고용 사본을 두길 원하면(공저자와 공유 등):

1. 편집기에서 원본 `.tex`를 열고 내용을 읽는다. Overleaf 편집기는 CodeMirror 6이라
   `document.querySelector('.cm-content').cmView.view`로 뷰를 얻고 `view.state.doc.toString()`으로 전체 텍스트를 읽는다.
2. 파일 트리의 **Add → New file**로 `<이름>_sub.tex`를 만든다(프로젝트 최상위).
3. 새 파일이 열린 것(`aria-selected` 트리 항목 이름)과 문서 길이가 0인 것을 확인한 뒤
   `view.dispatch({changes:{from:0,to:0,insert:<정리된 텍스트>}})`로 넣는다.
4. **Recompile** 후 로그에 `./<이름>_sub.tex`가 나오는지 확인한다. Overleaf는 **열려 있는 파일**을 컴파일한다(그 파일에 `\documentclass`가 있을 때).
5. 원본과 사본의 PDF를 비교한다 — 각 쪽을 `scrollIntoView()`해서 `.textLayer`의 텍스트를 모아 쪽별로 비교.

주의:

- 원본 `.tex`는 고치지 않는다. 사용자가 본문 수정을 요청하면 **두 파일 모두**에 반영해야 한다.
  수정 뒤에는 "주석과 매크로 정의를 뺀 나머지 줄이 두 파일에서 같은지" 비교해 어긋남을 잡는다.
- 수정 전에는 반드시 현재 선택된 파일 이름을 확인한다. 다른 파일이 열려 있으면 엉뚱한 곳을 고치게 된다.
- `javascript_tool` 출력은 1,000자 남짓에서 잘린다. 긴 줄은 나눠서 읽는다.
- 출력에 `?`나 `=`가 많으면 `[BLOCKED: Cookie/query string data]`로 막힐 수 있다.
  `.replace(/\?/g,'(q)').replace(/=/g,'(eq)')`처럼 바꿔서 반환한다.
- 편집은 `old` 문자열이 문서에 정확히 한 번 나오는지 확인하고 넣는다. 줄 번호는 다른 사람이 고치면 바뀐다.

## 4. 그림이 바뀌었을 때

사용자가 새 그림(`..._v2.pdf` 등)을 올렸다고 하면:

1. 파일 트리에서 새 파일이 실제로 있는지 확인(`figures` 폴더를 펼쳐야 보인다).
2. 원본과 `_sub.tex` **둘 다**의 `\includegraphics` 경로를 바꾼다. 두 파일의 기존 경로가 서로 다를 수 있으니 각각 확인한다.
3. 둘 다 재컴파일해 에러가 없는지 본다.
4. 본문에 그림에서 읽은 수치가 있으면 새 그림과 맞는지 사용자에게 확인을 요청한다.

## 5. 투고 전에 같이 볼 것

- 파일명에 한글·공백·괄호가 없는지(Elsevier 빌드에서 실패할 수 있음).
- BibTeX 경고가 없는지.
- 저널이 `.bbl`을 요구하는지 — 요구하면 로컬 컴파일로 만든 `.bbl`을 폴더에 추가.
- 로컬 TeX Live와 Overleaf의 TeX Live 버전이 달라도 쪽수가 같은지.

## 6. 필요한 것

- `python3`(표준 라이브러리만 씀)
- 컴파일 비교에 `latexmk`, `pdfinfo`, `pdftotext`(TeX Live + poppler). 없으면 컴파일 비교만 건너뛴다.
- Overleaf 쪽 작업에는 claude-in-chrome 연결.
